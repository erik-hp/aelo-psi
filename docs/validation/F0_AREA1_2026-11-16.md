| Achado | Evidência anterior | Correção e verificação |
| --- | --- | --- |
| Origens inseguras aceitas na inicialização HTTPS | 6 casos aceitaram HTTP, wildcard ou credenciais em CORS/CSRF | Em HTTPS, exigir origens exatas HTTPS, sem caminho/query/fragmento, credenciais, wildcard ou porta inválida; testes aprovados |
| Segredos reutilizados entre funções | 4 casos aceitaram a mesma chave entre Django, auditoria, IA ou chave clínica codificada | Recusar material repetido entre funções e chaves clínicas duplicadas; erro não imprime segredo |
| Cabeçalhos de segurança duplicados em respostas da API pelo proxy | Smoke real falhou ao exigir `X-Content-Type-Options: nosniff` único | `defer` no bloco Caddy aplica os valores após o upstream; smoke aprovado |
| Frontend HTTPS sem HSTS | Smoke ampliado falhou em `Frontend HTTPS response lacks HSTS` | HSTS de um ano somente nas respostas HTTPS, sem preload/subdomínios; smoke aprovado |
| Backup Git enviado ao contexto Docker | Inspeção sem leitura de conteúdo confirmou `.git-backup-before-monorepo` em imagem backend antiga | Exclusão nos dois contextos, incluindo `.git` no frontend e variantes de `.env` no backend; dois builds de inspeção aprovados |

## Reprodução

Os comandos a seguir partem da raiz. Os nomes de projeto isolam o banco e a CA de teste, e o compose TLS não publica portas no host.

```powershell
docker compose -p aelo-tls-validation -f Backend/docker-compose.tls-test.yml run --build --rm tls_smoke
docker compose -p aelo-tls-validation -f Backend/docker-compose.tls-test.yml run --rm --no-deps -e DJANGO_SETTINGS_MODULE=config.settings -e DJANGO_REQUIRE_HTTPS=False -e DJANGO_TRUST_PROXY_HEADERS=False migrate_tls python -m pytest -c pytest.postgres.ini -q -p no:cacheprovider
docker compose -p aelo-tls-validation -f Backend/docker-compose.tls-test.yml run --rm --no-deps migrate_tls python manage.py check --deploy --fail-level ERROR
docker compose -p aelo-tls-validation -f Backend/docker-compose.tls-test.yml down --volumes
docker build --network none -f Backend/docker/Dockerfile.context-check -t aelo-context-backend Backend
docker build --network none -f Backend/docker/Dockerfile.context-check -t aelo-context-frontend Frontend
```

Nesta rodada, o projeto foi `aelo-f0-area1-20261116`, com override local de imagens em `reports/f0-area1-20261116.images.yml` e `up --no-build` seguido de `run --no-deps`. O `.env` real não foi exibido nem alterado; os serviços usam variáveis sintéticas explícitas. Não houve alteração de DNS, certificados do host ou exposição pública. A nova etapa HTTPS no workflow foi preparada, mas ainda não executada remotamente.

Ao final, `down --volumes` encerrou exclusivamente esse projeto e removeu sua CA. A consulta por labels confirmou ausência de containers/volumes do projeto. Imagens antigas e arquivos pessoais foram preservados.
